Video Walkthrough — Quickstart

Use Windows PowerShell and the explicit content path below. Install once; update the same site afterward.

Have ready: approved script execution/signing, Windows PowerShell 5.1 (64-bit), .NET 4.7.2+, SPO/Graph modules, tenant ID and SharePoint hostname. For installation: an account with SharePoint Administrator or Global Administrator and approved Graph consent. You sign in with that one account twice, and it becomes the site primary owner. Business owners without an admin role are added after deployment. Keep the package and work folder outside OneDrive.

A. Start the installation

  1. Extract all package files outside OneDrive.

    Example: C:\VideoWalkthroughPackage. Keep Content.zip and the scripts together. Use your actual folder in every command below.

  2. Open 64-bit Windows PowerShell 5.1.

    Review scripts and use your approved signing/execution policy. This guide does not bypass it.

    Set-Location 'C:\VideoWalkthroughPackage'
  3. Run the help check with an explicit content path.
    .\Deploy-VideoWalkthrough.ps1 -ContentZipPath 'C:\VideoWalkthroughPackage\Content.zip' -Help

    The first line should read Deploy-VideoWalkthrough v2.2.1. If it does not, you extracted an older package. If a red error appears, stop.

    v2.2.1 also fixes the Start-VideoWalkthrough.cmd launcher that failed in v2.2, but the fixed launcher has not yet been retested on Windows. Use the commands in this guide.

  4. Run ONE command for your actual tenant cloud.

    GCC lab:

    .\Deploy-VideoWalkthrough.ps1 -ContentZipPath 'C:\VideoWalkthroughPackage\Content.zip' -Cloud GCC

    Commercial tenant:

    .\Deploy-VideoWalkthrough.ps1 -ContentZipPath 'C:\VideoWalkthroughPackage\Content.zip' -Cloud Commercial
  5. Choose S and answer the wizard prompts.

    URL slug: lowercase letters, digits and hyphens (uppercase is converted for you). Use your tenant ID and primary SharePoint hostname. The wizard re-asks any answer it cannot accept. At Cloud, press Enter to retain the choice above.

    Prompt / stepAccountRole needed
    Both browser sign-ins (Graph, then SharePoint admin)The installing adminSharePoint Administrator or Global Administrator
    Site primary ownerSet automatically to the installing admin (no prompt)Same as above
    Co-owners (step 7)Business owners, content ownersNone

    The wizard shows a yellow sign-in notice and, after sign-in, prints which account became the owner. Optional app ID: Enter unless supplied by your administrator. Embedded HTML: N for this hosted test.

    Work folder: press Enter for the full path shown, or type a full local path. Do not answer Y. Record this folder for future updates.

  6. Complete sign-in; verify the returned page and videos.

    Use the intended lab/site administrator. If the sign-in window is hidden, use Alt+Tab. Success ends with SharePoint page: ... (state: published) and videoCount : 11. Grant approved viewers Read access, then test playback as a viewer. Keep the saved deployment state.

  7. Optional: add co-owners.

    The wizard sets one primary owner (the admin you signed in with). Add business or content owners here; they need no admin role. They become site collection administrators. Run as a SharePoint Administrator or Global Administrator:

    Connect-SPOService -Url https://<tenant>-admin.sharepoint.com
'<user1 UPN>','<user2 UPN>' | ForEach-Object { Set-SPOUser -Site https://<tenant>.sharepoint.com/sites/<slug> -LoginName $_ -IsSiteCollectionAdmin $true }
  8. If the run fails after the site is created, resume it. Do not start over.

    Rerun with the same answers as the failed run (including the Cloud value you chose), your work folder, and -ReuseExistingSite. Uploaded videos are verified and skipped.

    .\Deploy-VideoWalkthrough.ps1 -NonInteractive -OrgName '<org>' -SiteName '<site title>' -SiteSlug <slug> -SharePointHost <tenant>.sharepoint.com -TenantId <tenant GUID> -OwnerUpn <admin UPN> -Cloud <GCC|Commercial> -WorkFolder '<work folder>' -ReuseExistingSite

    Add -EmbedVideos if the first run created the embedded HTML. The error text names the Graph error code; keep it for support.

  9. Interactive guide and Home page: automatic.

    Deploy finishes by running Publish-WalkthroughHome.ps1 itself: the site Home page then links to the interactive guide, videos open in the SharePoint player and PDFs are ready. Expect one more sign-in prompt (same admin) near the end. Run it yourself only to repeat it, for example after a content update or if Deploy reports that this last step failed:

    Set-Location 'C:\VideoWalkthroughPackage'
.\Publish-WalkthroughHome.ps1 -WorkFolder '<work folder>' -Force

    Use the same work folder Deploy used; the site, hostname and tenant are read from it. It uploads the interactive walkthrough next to the videos, builds the card PDFs with Microsoft Edge, and rebuilds Home.aspx with an Open the interactive walkthrough link plus direct video links. Video buttons open the SharePoint player; export buttons open the PDFs. Safe to rerun; the previous Home layout is saved in the work folder. Use -SkipPdf if Edge is not available.

B. Replace content later

After installation only. The updater has not yet been tested on Windows; run the preview below first.

  1. Back up the work folder; replace same-named videos.

    Use <work folder>\videos, not content\videos. Do not edit state or checksums.

  2. Run the updater from PowerShell; choose R.
    Set-Location 'C:\VideoWalkthroughPackage'
.\Update-VideoWalkthrough.ps1 -WorkFolder '<work folder>'

    Choose R for local replacements.

  3. Review the changes; enter Y to proceed.

    Check the target site and changed files. Unchanged videos are skipped; removed references do not delete hosted files.

  4. Authenticate and let the update finish.

    Use an account authorized for the existing site. Do not run a new-site deployment to replace content.

  5. Open the same page URL and test the changed videos.

    Video-only changes keep the existing page. Keep the update history and saved deployment state.

Preview without changing anything

Set-Location 'C:\VideoWalkthroughPackage'
.\Update-VideoWalkthrough.ps1 `
  -WorkFolder 'C:\VideoWalkthrough\governance-videos' `
  -WhatIf

Use your actual package and work folders.

C. Remove a deployment and rebuild

Use this to start over, for example after a test install or a wrong work folder. It deletes only the site recorded in that work folder's deployment-state.json, and asks you to type the site slug before deleting. The purge is permanent: the site, videos, PDFs and page cannot be restored. Requires SharePoint Administrator.

  1. Preview the removal (changes nothing).
    Set-Location 'C:\VideoWalkthroughPackage'
.\Remove-VideoWalkthrough.ps1 -WorkFolder '<work folder>' -WhatIf
  2. Remove the site, purge it, and retire the work folder.
    .\Remove-VideoWalkthrough.ps1 -WorkFolder '<work folder>' -Force

    Sign in as a SharePoint Administrator, then type the slug when asked. The site is deleted and purged from the SharePoint recycle bin, so the URL can be reused. The work folder is renamed to <work folder>-removed-<date>, not deleted. Add -KeepInRecycleBin to keep the site restorable for 93 days; the URL then stays reserved.

  3. Wait a few minutes, then rebuild with a full work-folder path.
    .\Deploy-VideoWalkthrough.ps1 -ContentZipPath 'C:\VideoWalkthroughPackage\Content.zip' -Cloud GCC
.\Publish-WalkthroughHome.ps1 -WorkFolder '<work folder>' -Force

    Follow section A; Deploy also publishes the Home page. If Deploy says the URL is still in the recycle bin, wait a few more minutes and rerun it.

Manual removal (if the script cannot be used)
Connect-SPOService -Url https://<tenant>-admin.sharepoint.com
Remove-SPOSite -Identity https://<tenant>.sharepoint.com/sites/<slug>
Remove-SPODeletedSite -Identity https://<tenant>.sharepoint.com/sites/<slug>

Then rename or delete the old work folder before rebuilding; Deploy requires an empty work folder. Remove-SPODeletedSite is permanent.

Stop on a conflict. Review site identity, permissions or edited assets; do not edit checkpoint hashes. If interrupted, keep the pending journal and rerun the same inputs; stop if reconciliation is required.
Only if your execution policy permits unblocking reviewed scripts
Set-Location 'C:\VideoWalkthroughPackage'
Unblock-File -LiteralPath '.\Deploy-VideoWalkthrough.ps1'
Unblock-File -LiteralPath '.\VideoWalkthrough.Common.ps1'
Unblock-File -LiteralPath '.\Update-VideoWalkthrough.ps1'

Unblocking does not satisfy AllSigned or override enforced policy. See the README for prerequisites and support.

New release with changed text or added videos
Set-Location 'C:\VideoWalkthroughPackage'
.\Update-VideoWalkthrough.ps1 `
  -WorkFolder 'C:\VideoWalkthrough\governance-videos' `
  -ContentZipPath 'C:\WalkthroughRelease\Content.zip' `
  -UpdatePage

Use your own paths and the supplied content ZIP. New filenames must be referenced by updated source HTML. -UpdatePage regenerates hosted text and links; stop if the page has conflicting edits.
